font-family: "Times-Roman", "Times New Roman", serif;
font-size: 14pt;
line-height: 1.15;
text-align: justify;

**Соответствие инструкции:** ✅ шрифт, ✅ размер 14pt, ✅ интервал 1.15, ✅ отступ 1.25см, ✅ выравнивание по ширине.  
Левое поле 30мм — по инструкции (≥30мм для документов постоянного хранения). ✅

## Проблемы, требующие исправления

### 🔴 КРИТИЧНО: id=45 — display:flex в bottom

**Файл:** `cam_documents.bottom` для id=45  
**Проблема:** Dompdf не поддерживает Flexbox. Строка подписи не отображается.

```html
<!-- ТЕКУЩИЙ (сломан в Dompdf): -->
<div style="margin-top: 50px; display: flex; justify-content: space-between; align-items: flex-end;">
<div>Министр социального развития<br>Московской области</div>
{{ minister_fio }}</div>
```

```html
<!-- ИСПРАВЛЕННЫЙ (таблица без рамок): -->
<p>&nbsp;</p>
<p>&nbsp;</p>
<table style="border-collapse: collapse; width: 100%; border-style: hidden;" border="0">
<tbody>
<tr>
<td style="width: 40%; vertical-align: top; border-style: hidden;">Министр социального развития<br>Московской области</td>
<td style="text-align: right; width: 20%; border-style: hidden;">{{ sign_2 | raw }}</td>
<td style="text-align: right; width: 40%; border-style: hidden;">{{ minister_fio }}</td>
</tr>
</tbody>
</table>
```

Аналогичный рабочий паттерн используется в id=2, 27, 28.

---

### 🔴 КРИТИЧНО: id=45 — body использует div+margin вместо p с CSS

**Проблема:** Тело документа id=45 написано через `<div style="text-indent: 40px; ...">` вместо `<p>`. Глобальный CSS `p { text-indent: 1.25cm; }` не применяется.  
Visually: отступы нестандартные (40px ≈ 10.6мм вместо 12.5мм), выравнивание не согласовано с остальными приказами.

**Решение:** Перевести на `<p>` теги (как в id=27, 28). Межстрочный интервал и отступы придут из глобального CSS автоматически.

---

### 🟡 ВАЖНО: Межстрочный интервал для актов — 1.15 вместо 1.0

**Проблема:** Глобальный CSS задаёт `line-height: 1.15` для всех документов. Образцы актов (ФХД Шатурский, МБТ Клин, НГО) используют `1.0×` (одинарный).  
Инструкция: межстрочный — 1-1.5× (оба варианта допустимы), но внешний вид PDF не совпадает с образцами.

**Расположение:** `core/ajaxHandlers/planPdf.php` строка ~547 (глобальный CSS `body`) и строка 697 (`actHtml` CSS).

**Решение:** Добавить условный CSS для `$documentacial == 2`:
```php
// Около строки 547, в основном CSS
$lineHeightCss = ($documentacial == 2) ? '1.0' : '1.15';
// Затем в CSS: line-height: ' . $lineHeightCss . ';
```
Аналогично в CSS для `$actHtml` (строка ~697+).

---

### 🟡 ВАЖНО: id=2 body — "No 19РВ-137" вместо "№ 19РВ-137"

**Проблема:** В тексте тела приказа id=2 используется латинская "No" вместо знака "№":  
```
от 27.12.2017 No 19РВ-137
```
В образцах: `№ 19РВ-137` (знак номера, как принято в русских документах).

**Также:** Аналогичная ошибка в header id=17 (`No 19РВ-137`).

---

### 🟡 ВАЖНО: id=17 header — захардкожено ФИО "Е.В. Ляхова"

**Проблема:** В header акта ФХД (id=17) жёстко прописано имя:
```html
<td style="text-align: right; ..."><span style="text-align: start;">Е.В. Ляхова</span></td>
```
Аналогично в headers актов id=18, 30, 32, 33.

**Решение:** Заменить на переменную `{{ chief_name }}` или использовать существующую переменную. Нужно уточнить какая переменная используется в этом контексте. Пока — баг данных, не CSS.

---

### 🟡 ВАЖНО: id=45 header — "МИНИСТР" вместо "МИНИСТЕРСТВО"

**Текущий header id=45:**
```html
<div style="font-size: 16pt; ...">МИНИСТР<br>СОЦИАЛЬНОГО РАЗВИТИЯ<br>МОСКОВСКОЙ ОБЛАСТИ</div>
```

**Все остальные приказы (id=2, 27, 28):**
```html
<h3>МИНИСТЕРСТВО<br>СОЦИАЛЬНОГО РАЗВИТИЯ<br>МОСКОВСКОЙ ОБЛАСТИ</h3>
```

Образец внепланового приказа (`Приказ о внеплановой проверке_20П-512.pdf`) — PDF, визуально идентичен другим приказам Министерства (со шапкой МИНИСТЕРСТВА, не МИНИСТРА). Шапка id=45 некорректна.

---

### 🟠 НЕЗНАЧИТЕЛЬНО: id=28 body — жёстко прописана дата "15 декабря 2024 года"

**Текущий текст:**
```
на 2025 год, утвержденного министром социального развития Московской области 15 декабря 2024 года:
```

**Проблема:** Дата утверждения плана хардкожена. При генерации документов для другого года будет неверная дата.

**Решение:** Заменить на `{{ plan_approve_date }}` или `{{ plan_year | minus(1) }} год`.
